# Stock MSVC build harness: review and proposed fixes

Review baseline: [`899ad7d`](https://github.com/pchemguy/SQLite-ICU-MinGW/commit/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a). Scope: `sqlite_msbuild.bat`, `msbuild_check.bat`, `download_file.bat`, and `extract_archive.bat`. The Tcl warning in §7 is the only code change made with this review. The remaining fixes below are proposals, not implemented behavior. The user guide is unchanged.

## Decisions: retain the existing behavior

| Finding | Disposition |
| --- | --- |
| 1. Artifact collection | Best effort. [The collector](https://github.com/pchemguy/SQLite-ICU-MinGW/blob/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a/Current/MSVC/stock/sqlite_msbuild.bat#L700-L721) clears files directly under `out\bin`, copies available products, and returns success even when a copy fails. The include and library directories are not cleared. Exit 0 is not a guarantee of a complete distribution. The obsolete `%PROJDIR%\src\*.h` copy is already gone. Carry this contract into the guide when it is next revised. |
| 2. Build-directory ownership | One base directory is for **one build**. A different target architecture, build configuration, or dependency installation requires a separate base directory. Reusing a populated base for a different build is unsupported. No configuration keys, architecture subdirectories, or automatic reconfiguration are proposed. |
| 6. NMake target forwarding | Keep the existing dispatch and pre/post processing. No special handling for `clean` or other targets is proposed. |
| 14. Diagnostic exit status | Not reopened here. `env`, `tcl-test`, and `tcl-env` still invoke NMake before download/extraction and return 100. |

## Download and cache: findings 3, 5, 10 and 11

[Shared downloader](https://github.com/pchemguy/SQLite-ICU-MinGW/blob/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a/Current/MSVC/stock/download_file.bat#L34-L35) · [GET and cache check](https://github.com/pchemguy/SQLite-ICU-MinGW/blob/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a/Current/MSVC/stock/download_file.bat#L62-L86) · [HEAD parser](https://github.com/pchemguy/SQLite-ICU-MinGW/blob/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a/Current/MSVC/stock/download_file.bat#L109-L136) · [ZLIB caller](https://github.com/pchemguy/SQLite-ICU-MinGW/blob/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a/Current/MSVC/stock/sqlite_msbuild.bat#L411-L429)

**5 — Check the cache before any network operation.** In `download_file.bat`, validate the arguments and return success for an existing, completed target before issuing HEAD or GET. In `:ZLIB_DOWNLOAD`, check the final `%CACHEDIR%\zlib.tar.gz` *before* resolving `/releases/latest`; fixing only the helper still leaves an online dependency. A cache hit means “reuse this archive,” not “check for a new release.” The first adoption of this policy must also account for potentially partial files left by older versions: validate or replace a suspect existing archive; the new write protocol cannot retroactively certify it.

**3 — Give the final filename one meaning: ready for reuse.** On a cache miss, download into a sibling `<target>.part`, never into `<target>`. Capture cURL's status immediately. On failure, return that status and discard the partial file; a leftover `.part` is never a hit. After success, have the archive caller validate the payload (for these two sources, `tar -tf` and the expected archive layout are suitable checks), then rename to the final path on the same volume and check the rename. If archive validation is part of publication, perform it before the rename, not on the next invocation. `--remove-on-error` is optional cleanup, not the correctness mechanism: it requires [cURL 7.83.0 or later](https://curl.se/docs/manpage.html#--remove-on-error). Explicit cleanup also works with older Windows cURL builds.

**10 — Check the response that supplied the file.** Use one redirect-following GET on a cache miss. Let `--dump-header` keep the full header chain for diagnosis if wanted, but use `--write-out` for the final status and content type. In a `.bat`, those fields are `%%{http_code}` and `%%{content_type}`. Strip parameters after `;`, trim whitespace and compare the media type case-insensitively: `text/html; charset=utf-8` is HTML. Missing media type or `application/octet-stream` proves nothing either way; archive validation decides. This also catches HTML returned only on GET, which a successful HEAD cannot rule out.

**11 — Preserve arguments across CMD parsing.** Pass the URL as `-- "%URL%"` on the cURL command, quote output and log paths, and quote the filename inside `for /f "usebackq ..."` if a log is read. Validate all three arguments before opening any logs. Avoid forwarding `%*` through another `call` merely to reach an internal label: `call` introduces another expansion pass. Read the three parameters once with delayed expansion disabled, and have the labels use those local variables. This keeps literal `!` from being consumed inside the helper. If future callers must accept arbitrary percent-encoded URLs, test the outer batch-to-batch `call` as well; quoting alone does not suppress percent expansion.

## Export generation: finding 4 and x86 verification

[:SQLITE_BUILD](https://github.com/pchemguy/SQLite-ICU-MinGW/blob/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a/Current/MSVC/stock/sqlite_msbuild.bat#L649-L686) first asks NMake for `sqlite3.def`, then truncates it and appends filtered output via `exports.txt`. A failed enumeration or interrupted prior run can therefore spoil a usable definition file.

**First choice for the stock harness:** keep the NMake-generated `.def` if it contains the intended public exports. SQLite's [upstream `Makefile.msc`](https://github.com/sqlite/sqlite/blob/master/Makefile.msc) already normalizes an optional leading underscore and trailing calling-convention suffix for the SQLite API families it selects. Establish whether this stock build actually requires any additional *DLL exports*. An extension being callable through SQL is not itself a reason to export its C initializer. Do not remove the custom path until the export sets have been compared.

**If additional exports are required:** retain the upstream file as the baseline; add only the intended public names. Run `dumpbin` to a fresh raw file and check its own exit status before filtering. Recreate, do not append to, the intermediate list; sort and deduplicate canonical names. Write a sibling candidate `.def` and require the baseline exports (including `sqlite3_open` and `sqlite3_close`) plus the explicitly expected additions. Only then replace the final `.def`. An enumeration, parsing, validation, or rename failure must fail the stage without publishing an incomplete list.

**Native acceptance test, not yet run:** use separate fresh x86 and x64 bases. Save the upstream `.def`, raw `dumpbin /linkermember:2` output, final `.def`, and `dumpbin /exports sqlite3.dll`. Verify the expected public names, not just the number of rows. In each matching MSVC shell, compile and link a tiny C client against the *packaged import library*, put the matching DLLs beside it, then run it to open `:memory:` and close the database. A DLL export listing alone does not test the `.lib` that downstream clients use.

## Environment checks: findings 7 and 8

**7 — Implemented:** [`c8888e2`](https://github.com/pchemguy/SQLite-ICU-MinGW/commit/c8888e2399cbb2794d8505c423988c876e8625dd) keeps the `where tclsh.exe` probe. If missing, it prints a warning and leaves `ERROR_STATUS` untouched. It does not reset an earlier error. When found, the existing informational output is unchanged. This does not change `TCLSH_CMD` or how the build uses `jimsh0.exe`.

**8 — Validate the selected target, not the host.** Accept only `x86` and `x64` (case-insensitive) for `VSCMD_ARG_TGT_ARCH`. Fail on an empty or unsupported value before deriving ICU paths or using `/machine:`. When `USE_ICU=1`, also check the actual Conda ICU binary proposed for staging, e.g. `icuuc<major>.dll`, with `dumpbin /headers`. Compare its [PE machine type](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#machine-types) with the requested target (`14C` for x86, `8664` for x64). Fail with the binary path, expected target and observed machine. Neither the host architecture nor the directory name is evidence of binary architecture.

**Other checker proposals.** Fix the [`VCINSTALLDIR` diagnostic](https://github.com/pchemguy/SQLite-ICU-MinGW/blob/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a/Current/MSVC/stock/msbuild_check.bat#L29-L33) to name the variable actually tested; this does not require adding a separate `VSINSTALLDIR` requirement. Check `dumpbin.exe` and `lib.exe` for the build/export path. Check `curl.exe` only on a network path and the exact Windows `tar.exe` when validating or extracting an archive. This keeps an unused downloader from becoming a prerequisite for a warm, offline build. Do not add a requirement for `msbuild.exe`: this harness invokes NMake.

## Dependency staging: findings 9, 12 and 13

**9 — Stage ICU as one set.** [The three existing markers](https://github.com/pchemguy/SQLite-ICU-MinGW/blob/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a/Current/MSVC/stock/sqlite_msbuild.bat#L516-L528) permit a partially populated tree to be completed with files from another installation. On a fresh build, copy headers, import libraries and runtime files to a new sibling staging directory; check each operation and the required headers, link inputs and versioned runtime/data DLLs. Apply the existing DLL exclusions there. Only after validation write a completion marker and rename the staged tree to the existing `compat\icu` layout. On repeat runs reuse that complete set; if the final tree exists but is incomplete, fail with a recovery message rather than filling the gaps. To change ICU installations use a fresh base (§2). This preserves all downstream paths without introducing a build key.

**12 — Give tar the destination explicitly.** In [`extract_archive.bat`](https://github.com/pchemguy/SQLite-ICU-MinGW/blob/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a/Current/MSVC/stock/extract_archive.bat#L28-L65), validate the arguments, resolve the input archive and destination to absolute paths, verify the destination is a directory, and use `"%TAR%" -x -f "%SRC%" -C "%DST%"`. Initialize the Windows tar path locally if it is not provided. Check tar's exit status immediately. The helper should not depend on or change the caller's working directory. Do not universally require the *final* reuse flag to exist immediately after tar: SQLite can validate its makefile then, but ZLIB's final flag is established only after the directory rename below. An interrupted extraction must not count as complete merely because a makefile was unpacked early; use a completion marker written after successful extraction and validation, or publish a validated staging directory.

**13 — Resolve and normalize ZLIB only when needed.** On an archive miss, run cURL separately from `for /f`, write the effective release URL to a file, and check cURL's status before parsing it. Clear any inherited tag, require the expected repository's `/releases/tag/v<version>` URL with a nonempty supported version, then construct the asset URL. Do not strip the first character of an unchecked value. In [`:ZLIB_EXTRACT`](https://github.com/pchemguy/SQLite-ICU-MinGW/blob/899ad7d6a46638cbe3d1e8f083a7f60639f2d42a/Current/MSVC/stock/sqlite_msbuild.bat#L441-L460), return immediately for a confirmed complete `compat\zlib`. Otherwise extract into a fresh staging directory, require exactly one `zlib-<version>` directory containing `win32\Makefile.msc`, and move that exact directory to its final name. Check the move and final marker. Reject an incomplete existing destination rather than moving into it. This also works offline with a cached archive: the extracted directory identifies the version, so the tag need not be resolved again.

## Verification boundary

The Tcl change was checked by tracing the actual missing/found branch statements with an initial status of both 0 and 1. It was not executed under native CMD. Windows acceptance cases beyond the x86/x64 export test above: a fully cached build with the network unavailable; an interrupted GET followed by retry; HTML after a redirect; paths with spaces and a URL with a query string; a failed or unexpected archive extraction; and a partial ICU tree. These are proposed checks, not claimed test results.
